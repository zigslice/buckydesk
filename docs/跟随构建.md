# 长期跟随构建

BuckyDesk 不编译 BuckyOS，也不把上游仓库设成子模块。上游每天在 `main` 上打好各平台的安装载荷；本仓库只钉住其中的无界面内核，界面继续用本仓库里的 gd5 页面。

钉住的是一次成功构建的版本号、提交和文件摘要，不是分支名 `main`。

## 钉哪些仓库

| 来源 | 跟随什么 | 不跟随什么 |
| --- | --- | --- |
| [buckyos/buckyos](https://github.com/buckyos/buckyos) | `main` 上最近一次成功的 `Build All BuckyOS Artifacts` 载荷 | 源码树、Web 桌面、frame 服务、`.pikg`、GitHub Release（最新 Release 仍是 2026-05 的 0.6.0，而 `src/VERSION` 已是 0.7.0） |
| [buckyos/cyfs-gateway](https://github.com/buckyos/cyfs-gateway) | 同名工作流里成功的 `cyfs-gateway` 载荷 | `web3-gateway`、BNS 网页、测试服务 |
| [zigslice/gd5](https://github.com/zigslice/gd5) | 一个提交。页面从这份源码以 ESM 加载 | 它的 `master` 不直接进安装包 |

两个内核仓库各自发版，日期可以差一天。锁文件里分成两项，不假设同一次构建。

## 载荷从哪下载

GitHub Actions 的 artifact 会过期。长期地址是公开下载站，对象在 R2 桶 `buckyos-installer`：

```text
https://buckyos-installer.tbudr.top/buckyos/buckyos-<系统>-<架构>-<版本>.tar.gz
https://buckyos-installer.tbudr.top/cyfs-gateway/cyfs-gateway-<系统>-<架构>-<版本>.tar.gz
```

版本形如 `0.7.0+build261020`。系统与架构用上游的名字：`linux-amd64`、`linux-aarch64`、`apple-amd64`、`apple-aarch64`、`windows-amd64`。Windows 目前没有 arm64 载荷。

这个站点对 `HEAD` 返回 403，用 `GET` 可以下到文件。2026-10-20 能取到的例子：

- `buckyos-linux-amd64-0.7.0+build261020.tar.gz`（216770400 字节），对应提交 `cd85b4707e264298baec9ab0f1e9c3b22d2997c9`
- `cyfs-gateway-linux-amd64-0.7.0+build261019.tar.gz`（37626459 字节），对应提交 `13314d3c5a8116903876360574ea9f47182b3b1c`

包内是完整的 `buckyos/` 或网关 rootfs，里面包含我们不用的页面。下载后只解出下面这些路径。

从 `buckyos` 包：

```text
bin/node-daemon/
bin/system-config/
bin/verify-hub/
bin/scheduler/
bin/task-manager/
bin/kmsg/
bin/workflow/
etc/scheduler/
etc/boot_gateway.yaml
etc/cyfs_gateway.yaml
etc/node_gateway.json
etc/node_gateway_info.json
etc/node_gateway_params.json
etc/user_gateway.yaml
etc/post_gateway.yaml
```

从 `cyfs-gateway` 包：

```text
bin/cyfs-gateway/
etc/cyfs_gateway/
```

网关包里的 `etc/cyfs_gateway/` 覆盖 BuckyOS 包里的同名目录。`bin/test-server/` 不拷贝。

明确不拷贝：`bin/control-panel/`、`bin/node-active/`、`bin/opendan/`、`bin/repo-service/`、`bin/nfs-server/`、`bin/smb-service/`、`bin/msg-center/`、`bin/aicc/`、`bin/homestation/`、`bin/aiworkspace/`、`bin/buckyos`、`libexec/buckyos-tool/`、`data/cache/*.pikg`。

## 锁文件

仓库根目录放 `kernel.lock.json`，由跟随流程修改，人工合并后才生效。构建只读它，不访问上游 `main`。

```json
{
  "buckyos": {
    "repository": "buckyos/buckyos",
    "revision": "cd85b4707e264298baec9ab0f1e9c3b22d2997c9",
    "version": "0.7.0+build261020",
    "workflow_run": 39371479122,
    "payloads": {
      "linux-amd64": {
        "url": "https://buckyos-installer.tbudr.top/buckyos/buckyos-linux-amd64-0.7.0+build261020.tar.gz",
        "size": 216770400,
        "sha256": "<下载后填写>"
      }
    }
  },
  "cyfs-gateway": {
    "repository": "buckyos/cyfs-gateway",
    "revision": "13314d3c5a8116903876360574ea9f47182b3b1c",
    "version": "0.7.0+build261019",
    "workflow_run": 39223885720,
    "payloads": {}
  },
  "gd5": {
    "repository": "zigslice/gd5",
    "revision": "b643fbd026af8806607acd391c9ad84dc433751b"
  }
}
```

五个平台都要有 `url`、`size`、`sha256`。缺一个平台就不能给那个平台出安装包。`sha256` 对 tar.gz 原文计算。

gd5 只记提交。`bucky desk open` 把该提交的 `src/engine` 和 `src/ui` 放进 1016 的站点，和页面一起提供。不把 gd5 的 `master` 写进运行中的安装包。

## 日常跟随

每天一次，或在需要时手动跑：

1. 查 `buckyos/buckyos` 与 `buckyos/cyfs-gateway` 的 `build-all`，只认 `main` 上结论为成功的最近一次。
2. 从运行记录得到提交，从 artifact 名得到 `0.7.0+buildYYMMDD`。进行中的运行不用。
3. 和 `kernel.lock.json` 比较。提交和版本都没变就结束。
4. 变了就下载对应 tar.gz，核对大小，计算 sha256，只更新锁里变化的那一项。
5. 开一个 PR。PR 里写明旧版本、新版本、两个仓库的提交，以及这次没有改 gd5。
6. PR 的检查：按白名单解包，确认每个二进制都在，`node_daemon --version` 和 `cyfs_gateway` 的版本输出与锁一致。不在这台机器上编译 Rust。
7. 人看过再合并。不自动合并，因为内核接口变化会让 1016 的页面和 boot 失败。

gd5 单独跟随：`master` 有新提交时另开 PR，只改 `gd5.revision`。不和内核更新绑在同一次发布里。

## 本仓库怎么构建

```text
读 kernel.lock.json
  → 下载并校验两个 tar.gz
  → 按白名单解到 build/kernel/<平台>/
  → 取出钉住的 gd5 源码
  → 编译 bucky desk open，把内核目录和页面放进安装根
  → 安装根里没有 control-panel 的网页，也没有 BuckyOSApp
```

开发者机器和 CI 使用同一条命令。不克隆 `buckyos`，不运行 `buckyos-build`，不安装 Node、pnpm、Deno 来编译上游。

安装进用户机器时，这些二进制放到 BuckyDesk 自己的 `BUCKYOS_ROOT`，由 `bucky desk open` 拉起。浏览器只打开 `http://127.0.0.1:1016`。
