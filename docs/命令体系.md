# 命令体系

程序的命令只有这一棵树。终端和本机 HTTP 都调用它，后面给内核、身份补实现时只改这一处。

人打开的 `http://127.0.0.1:1016` 是工作区，场景写在 [用户场景](用户场景.md)。这棵树不铺在那一页上。准备、登录、文件、消息、Agent、模型、工作和重置都调用这棵树，结果写在这台电脑上。

## 目录

| 路径 | 内容 |
| --- | --- |
| `src/backend` | Rust 命令树、命令行入口、本机 HTTP |
| `src/frontend` | gd5 页面。`index.html` 由 `/` 提供，其余文件由 `/app/` 提供 |
| `src/frontend/vendor/gd5` | [gd5](https://github.com/zigslice/gd5) 子模块，固定在 `b643fbd026af8806607acd391c9ad84dc433751b` |

依赖是 `serde`、`serde_json`、`sha2`、`base64` 和 `ureq`。`ureq` 把摘要发给模型服务。`url`、`idna`、`zeroize` 钉在 Rust 1.83 能编译的版本。HTTP 用标准库的 `TcpListener`，页面不经过打包器。

## 两个面

每条命令带一个面：

| 面 | 含义 |
| --- | --- |
| `cli` | 只在终端运行 |
| `http` | 只从页面运行 |
| `both` | 两边都能运行 |

`desk open` 是 `cli`。页面所在的进程不能再把自己启动一次。页面请求它时，HTTP 返回 403，摘要说明只能在命令行运行。

终端入口是 `bucky <命令>`。页面先 `GET /api/commands` 拿到同一棵树，再 `POST /api/exec`，正文是 `{"argv":["desk","kernel","status"]}`。`argv` 不含程序名。

## 树

一个程序，两个分组。`desk` 是这台电脑。`cloud` 是这个 Zone 用域名从公网打开的那一面。两边共用同一份身份和同一个内核。

```
bucky
  version                 打印本壳版本
  commands                打印命令树
  desk                    这台电脑上的工作区
    open                  监听并打开浏览器          cli
      --bind <值>         默认 127.0.0.1:1016
      --no-open           不打开浏览器
      --frontend <值>     页面目录
      --gd5 <值>          gd5 目录
    kernel
      status              探测内核是否已在监听
      services            查看内核服务是否在听
      start               拉起内核                  这一版不拉起进程
      stop                停止内核                  这一版不拉起进程
    identity
      status              查看工作区身份
      activate            记下名字、密码和钥匙文件夹
        --name <值>
        --password <值>
        --key-folder <值>
      finish              把准备中的工作区标成就绪
      login               用管理密码进入
        --password <值>
      password            更换管理密码
        --current <值>
        --next <值>
      reset               删除记下的身份、工作区和域名
    workspace
      status              读出文件、消息、Agent 和工作
      file                新建、放入、改名、移动、删除
      work                新建、留下、撤销、标成看过
      agent               做助手、开始或停下、记下 Telegram
      person              认识的人，以及静音
      message reply       答复一条消息
      model               接上或断开模型服务
      summary             把文件做成摘要
      member add          再加一个能进入的人
      reach               记下本机想用的名字
      note                记下另一台电脑的地址
      language            记下语言
  cloud                   用域名从公网打开这个 Zone
    status                查看域名、DNS 和 80/443
    domain                查看或记下 Zone 的域名
      --name <值>         不带时只查看
```

选项只有 `--name` 和 `--name=值`。没有位置参数。未知命令、未知选项退出码 2。命令跑完但 `ok` 为 false，或者明确失败，退出码 1。成功是 0。

`bucky desk open` 监听成功后先打印 URL。没有 `--no-open` 时打开系统浏览器，然后停在这个进程里提供页面。目录默认是仓库里的 `src/frontend` 和 `src/frontend/vendor/gd5`，也可以用 `BUCKYDESK_FRONTEND`、`BUCKYDESK_GD5`。

1016 在 Linux 上属于 1024 以下的端口，需要额外权限。Windows 和 macOS 可以直接听这个端口。Linux 上绑不上时，用 `--bind 127.0.0.1:18016`。

## 页面能拿到的路径

| 路径 | 来源 |
| --- | --- |
| `/`、`/index.html` | `src/frontend/index.html` |
| `/app/*` | `src/frontend` 下的页面脚本和样式 |
| `/gd5/*` | gd5 源码，供 ESM 直接加载 |
| `GET /api/commands` | 命令树 JSON。字段是 `name`、`path`、`summary`、`surface`、`args`、`commands` |
| `POST /api/exec` | 按 `argv` 在 http 面分发 |

路径会做百分号解码。带 `..` 的路径不读文件。请求正文上限 3MB，响应带 `Connection: close`。

身份写在 `desk.json`。目录是环境变量 `BUCKYDESK_STATE`，否则是用户主目录下的 `.buckydesk`。文件里有 `phase`（`partial` 或 `ready`）、名字、密码哈希和钥匙文件夹路径。哈希与上游一致：`base64(SHA-256(password + name + ".buckyos"))`。返回里没有哈希，也没有密码。

`desk identity activate` 在还没有身份时写下 `partial`。已经是 `partial` 时拒绝，摘要是「上次没有完成。」已经 `ready` 时拒绝，摘要是「已经有工作区了。」`desk identity finish` 把 `partial` 标成 `ready`；已经 `ready` 时仍然成功。`desk identity reset` 删掉 `desk.json`、`cloud.json`，以及同目录里的 `workspace.json` 和文件内容。钥匙文件夹只记下路径，不在那里生成钥匙，也不写 `node_identity.json`。

工作区在 `workspace.json`。文件正文在同目录的 `blobs/`。模型密钥写在 `workspace.json` 里，返回给页面的是掩码。`workspace summary` 在服务地址以 `http://` 或 `https://` 开头时，向它的 `/chat/completions` 发一次请求，把返回的摘要放进工作。地址不是网址时，工作记成没有完成，今天里能看见。

`desk kernel status` 用大约 200 毫秒连接 `BUCKYDESK_KERNEL`，默认 `127.0.0.1:3180`。连上时 `attached` 为 true，摘要是「内核已经在这台电脑上运行。」连不上时摘要是「内核还没有在这台电脑上运行。」`desk kernel services` 同时看网关和其余内核服务。网关地址仍是 `BUCKYDESK_KERNEL`。其余服务用同一台主机上的固定端口：节点守护 3181、系统配置 3200、登录 3300、任务 3380、调度 3400、消息队列 4030、工作流 4070。网关在听时摘要是「网关已经在这台电脑上运行。」`desk kernel start` 和 `desk kernel stop` 的摘要是「这台电脑上还没有可拉起的内核。」

## cloud

`cloud` 是 Zone 的公网入口，不是第二个页面服务。别人从 `https://<应用主机名>` 进来，接到这台机器的 80/443（ZoneGateway），再进本机服务。3180 和 1016 仍然只给本机。没有公网地址时才走 SN；这里记下的是自己的域名。

域名写在状态目录的 `cloud.json`。Zone 是 `did:web:<域名>`，这台机器是 `did:web:ood1.<域名>`。`cloud domain --name` 记下这个名字；不带 `--name` 时和 `cloud status` 一样，只查看。

`cloud status` 做三件事：读已记下的域名，解析它的地址并试着在本机绑定这些地址，再看 `127.0.0.1` 的 80 和 443 是否在听。三件都成，`reachable` 为 true，摘要是「可以从网上打开 <域名>。」有域名但还对不上时，摘要是「已记下域名 <域名>。别人还不能从网上打开。」还没有域名时，摘要是「还没有域名。记下域名之后，才能从网上打开。」

云主机上的公网地址如果没有配在本机网卡上，解析到的地址绑不了，`dnsPointsHere` 为 false。这一版不改 DNS，不申请证书，不启动 ZoneGateway。

## 这一版不做

不下载内核包，不写 `node_identity.json`，不启动 `node-daemon`。`kernel status` 只探测 3180 上是否已有进程在听。见 [非 UI 内核](非ui内核.md)。

本地查看：

```
cargo run -p buckydesk -- desk open
```
