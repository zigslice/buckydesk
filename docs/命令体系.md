# 命令体系

程序的命令只有这一棵树。终端和本机 HTTP 都调用它，后面给内核、身份补实现时只改这一处。

人打开的 `http://127.0.0.1:1016` 是工作区，场景写在 [用户场景](用户场景.md)。这棵树不铺在那一页上。设名字、密码、登录、改密码和重置时，页面调用这棵树。文件、消息、Agent 和模型仍记在浏览器里。

## 目录

| 路径 | 内容 |
| --- | --- |
| `src/backend` | Rust 命令树、命令行入口、本机 HTTP |
| `src/frontend` | gd5 页面。`index.html` 由 `/` 提供，其余文件由 `/app/` 提供 |
| `src/frontend/vendor/gd5` | [gd5](https://github.com/zigslice/gd5) 子模块，固定在 `b643fbd026af8806607acd391c9ad84dc433751b` |

依赖是 `serde`、`serde_json`、`sha2` 和 `base64`。HTTP 用标准库的 `TcpListener`，页面不经过打包器。

## 两个面

每条命令带一个面：

| 面 | 含义 |
| --- | --- |
| `cli` | 只在终端运行 |
| `http` | 只从页面运行 |
| `both` | 两边都能运行 |

`server` 是 `cli`。页面所在的进程不能再把自己启动一次。页面请求它时，HTTP 返回 403，摘要说明只能在命令行运行。

终端入口是 `buckydesk <命令>`。页面先 `GET /api/commands` 拿到同一棵树，再 `POST /api/exec`，正文是 `{"argv":["kernel","status"]}`。`argv` 不含程序名。

## 树

```
buckydesk
  version                 打印本壳版本
  commands                打印命令树
  server                  监听并打开浏览器          cli
    --bind <值>           默认 127.0.0.1:1016
    --no-open             不打开浏览器
    --frontend <值>       页面目录
    --gd5 <值>            gd5 目录
  kernel
    status                探测内核是否已在监听
    start                 拉起内核                  这一版不拉起进程
    stop                  停止内核                  这一版不拉起进程
  identity
    status                查看工作区身份
    activate              记下名字、密码和钥匙文件夹
      --name <值>
      --password <值>
      --key-folder <值>
    finish                把准备中的工作区标成就绪
    login                 用管理密码进入
      --password <值>
    password              更换管理密码
      --current <值>
      --next <值>
    reset                 删除记下的身份
```

选项只有 `--name` 和 `--name=值`。没有位置参数。未知命令、未知选项退出码 2。命令跑完但 `ok` 为 false，或者明确失败，退出码 1。成功是 0。

`server` 监听成功后先打印 URL。没有 `--no-open` 时打开系统浏览器，然后停在这个进程里提供页面。目录默认是仓库里的 `src/frontend` 和 `src/frontend/vendor/gd5`，也可以用 `BUCKYDESK_FRONTEND`、`BUCKYDESK_GD5`。

1016 在 Linux 上属于 1024 以下的端口，需要额外权限。Windows 和 macOS 可以直接听这个端口。Linux 上绑不上时，用 `--bind 127.0.0.1:18016`。

## 页面能拿到的路径

| 路径 | 来源 |
| --- | --- |
| `/`、`/index.html` | `src/frontend/index.html` |
| `/app/*` | `src/frontend` 下的页面脚本和样式 |
| `/gd5/*` | gd5 源码，供 ESM 直接加载 |
| `GET /api/commands` | 命令树 JSON。字段是 `name`、`path`、`summary`、`surface`、`args`、`commands` |
| `POST /api/exec` | 按 `argv` 在 http 面分发 |

路径会做百分号解码。带 `..` 的路径不读文件。请求正文上限 64KB，响应带 `Connection: close`。

身份写在 `desk.json`。目录是环境变量 `BUCKYDESK_STATE`，否则是用户主目录下的 `.buckydesk`。文件里有 `phase`（`partial` 或 `ready`）、名字、密码哈希和钥匙文件夹路径。哈希与上游一致：`base64(SHA-256(password + name + ".buckyos"))`。返回里没有哈希，也没有密码。

`identity activate` 在还没有身份时写下 `partial`。已经是 `partial` 时拒绝，摘要是「上次没有完成。」已经 `ready` 时拒绝，摘要是「已经有工作区了。」`identity finish` 把 `partial` 标成 `ready`；已经 `ready` 时仍然成功。`identity reset` 删掉这个文件。钥匙文件夹只记下路径，不在那里生成钥匙，也不写 `node_identity.json`。

`kernel status` 用大约 200 毫秒连接 `BUCKYDESK_KERNEL`，默认 `127.0.0.1:3180`。连上时 `attached` 为 true，摘要是「内核已经在这台电脑上运行。」连不上时摘要是「内核还没有在这台电脑上运行。」`kernel start` 和 `kernel stop` 的摘要是「这台电脑上还没有可拉起的内核。」

## 这一版不做

不下载内核包，不写 `node_identity.json`，不启动 `node-daemon`。`kernel status` 只探测 3180 上是否已有进程在听。见 [非 UI 内核](非ui内核.md)。

本地查看：

```
cargo run -p buckydesk -- server
```
