# 命令体系

程序的命令只有这一棵树。终端和本机 HTTP 都调用它，后面给内核、身份补实现时只改这一处。

人打开的 `http://127.0.0.1:1016` 是工作区，场景写在 [用户场景](用户场景.md)。这棵树不铺在那一页上。准备、登录、文件、消息、Agent、模型、工作和重置都调用这棵树，结果写在这台电脑上。

## 目录

| 路径 | 内容 |
| --- | --- |
| `src/backend` | Rust 命令树、命令行入口、本机 HTTP |
| `src/frontend` | gd5 页面。`index.html` 由 `/` 提供，其余文件由 `/app/` 提供 |
| `src/frontend/vendor/gd5` | [gd5](https://github.com/zigslice/gd5) 子模块，固定在 `b643fbd026af8806607acd391c9ad84dc433751b` |

依赖是 `serde`、`serde_json`、`sha2`、`base64`、`ureq`、`url` 和 `idna`。`ureq` 把摘要发给模型服务，也用来从桌面连上云入口。`url`、`idna` 和 `zeroize` 钉在 Rust 1.83 能编译的版本。HTTP 用标准库的 `TcpListener`，页面不经过打包器。

## 两个面

每条命令带一个面：

| 面 | 含义 |
| --- | --- |
| `cli` | 只在终端运行 |
| `http` | 只从页面运行 |
| `both` | 两边都能运行 |

`desk open`、`cloud serve` 和 `desk entrance start` 都是 `cli`。页面所在的进程不能再把自己启动一次，向外连着的那一程也留在命令行。页面请求它们时，HTTP 返回 403，摘要说明只能在命令行运行。

终端入口是 `bucky <命令>`。页面先 `GET /api/commands` 拿到同一棵树，再 `POST /api/exec`，正文是 `{"argv":["desk","kernel","status"]}`。`argv` 不含程序名。

## 树

一个程序，两个分组。`desk` 是这台桌面。`cloud` 是给这些桌面的公网入口。云主机上不长自己的桌面。没有公网地址的桌面向外连到入口，访问再转回这台桌面。自己有固定公网地址和域名的桌面，入口就在它自己身上。

```
bucky
  version                 打印本壳版本
  commands                打印命令树
  desk                    这台电脑上的工作区
    open                  监听并打开浏览器          cli
      --bind <值>         默认 127.0.0.1:1016
      --no-open           不打开浏览器
      --frontend <值>     页面目录
      --gd5 <值>          gd5 目录
    kernel
      status              探测内核是否已在监听
      services            查看内核服务是否在听
      start               拉起内核                  这一版不拉起进程
      stop                停止内核                  这一版不拉起进程
    identity
      status              查看工作区身份
      activate            记下名字、密码和钥匙文件夹
        --name <值>
        --password <值>
        --key-folder <值>
      finish              把准备中的工作区标成就绪
      login               用管理密码进入
        --password <值>
      logout              离开这一次，并收回公网入口的登录
      password            更换管理密码
        --current <值>
        --next <值>
      reset               删除记下的身份、工作区和入口
    workspace
      status              读出文件、消息、Agent 和工作
      file                新建、放入、改名、移动、删除
      work                新建、留下、撤销、标成看过
      agent               做助手、开始或停下、记下 Telegram
      person              认识的人，以及静音
      message reply       答复一条消息
      model               接上或断开模型服务
      summary             把文件做成摘要
      member add          再加一个能进入的人
      reach               记下本机想用的名字
      note                记下另一台电脑的地址
      language            记下语言
    entrance              这台桌面的公网入口
      status              查看这台桌面接到哪里
      use                 记下云入口和这台桌面的名字
        --at <值>         云入口的地址
        --name <值>       这台桌面的名字
      start               向外连上云入口              cli
        --desk <值>       本机页面地址，默认 127.0.0.1:1016
  cloud                   给桌面的公网入口
    status                查看哪些桌面接了进来，哪些正连着
    serve                 在公网接住桌面连出来的访问  cli
      --bind <值>         默认 0.0.0.0:80
```

选项只有 `--name` 和 `--name=值`。没有位置参数。未知命令、未知选项退出码 2。命令跑完但 `ok` 为 false，或者明确失败，退出码 1。成功是 0。

`bucky desk open` 监听成功后先打印 URL。没有 `--no-open` 时打开系统浏览器，然后停在这个进程里提供页面。目录默认是仓库里的 `src/frontend` 和 `src/frontend/vendor/gd5`，也可以用 `BUCKYDESK_FRONTEND`、`BUCKYDESK_GD5`。

1016 在 Linux 上属于 1024 以下的端口，需要额外权限。Windows 和 macOS 可以直接听这个端口。Linux 上绑不上时，用 `--bind 127.0.0.1:18016`。

## 页面能拿到的路径

| 路径 | 来源 |
| --- | --- |
| `/`、`/index.html` | `src/frontend/index.html` |
| `/app/*` | `src/frontend` 下的页面脚本和样式 |
| `/gd5/*` | gd5 源码，供 ESM 直接加载 |
| `GET /api/commands` | 命令树 JSON。字段是 `name`、`path`、`summary`、`surface`、`args`、`commands` |
| `POST /api/exec` | 按 `argv` 在 http 面分发 |

路径会做百分号解码。带 `..` 的路径不读文件。请求正文上限 3MB，响应带 `Connection: close`。

身份写在 `desk.json`。目录是环境变量 `BUCKYDESK_STATE`，否则是用户主目录下的 `.buckydesk`。文件里有 `phase`（`partial` 或 `ready`）、名字、密码哈希和钥匙文件夹路径。哈希与上游一致：`base64(SHA-256(password + name + ".buckyos"))`。返回里没有哈希，也没有密码。

`desk identity activate` 在还没有身份时写下 `partial`。已经是 `partial` 时拒绝，摘要是「上次没有完成。」已经 `ready` 时拒绝，摘要是「已经有工作区了。」`desk identity finish` 把 `partial` 标成 `ready`；已经 `ready` 时仍然成功。`desk identity login` 成功时签发一次登录。返回里有 `token`，状态目录的 `session.json` 只存它的 SHA-256，权限是 `0600`。`desk identity logout`、`desk identity reset` 和成功的 `desk identity password` 都会删掉这次登录。`desk identity reset` 同时删掉 `desk.json`、`link.json`、`desktops.json`，以及同目录里的 `workspace.json` 和文件内容。以前留下的 `cloud.json`、`cert.pem`、`key.pem` 也会清掉。钥匙文件夹只记下路径，不在那里生成钥匙，也不写 `node_identity.json`。

工作区在 `workspace.json`。文件正文在同目录的 `blobs/`。模型密钥写在 `workspace.json` 里，返回给页面的是掩码。`workspace summary` 在服务地址以 `http://` 或 `https://` 开头时，向它的 `/chat/completions` 发一次请求，把返回的摘要放进工作。地址不是网址时，工作记成没有完成，今天里能看见。

`desk kernel status` 用大约 200 毫秒连接 `BUCKYDESK_KERNEL`，默认 `127.0.0.1:3180`。连上时 `attached` 为 true，摘要是「内核已经在这台电脑上运行。」连不上时摘要是「内核还没有在这台电脑上运行。」`desk kernel services` 同时看网关和其余内核服务。网关地址仍是 `BUCKYDESK_KERNEL`。其余服务用同一台主机上的固定端口：节点守护 3181、系统配置 3200、登录 3300、任务 3380、调度 3400、消息队列 4030、工作流 4070。网关在听时摘要是「网关已经在这台电脑上运行。」`desk kernel start` 和 `desk kernel stop` 的摘要是「这台电脑上还没有可拉起的内核。」

## 入口

云主机跑 `bucky cloud serve`，只做公网入口。默认听 `0.0.0.0:80`。Linux 上 80 需要额外权限，绑不上时用 `--bind 0.0.0.0:8080`。监听成功后打印实际地址，再打印「桌面从这里向外连。」浏览器留在每台桌面上。

每台桌面在「在别处打开」里记下入口地址和自己的名字，对应 `desk entrance use --at <入口> --name <名字>`。两个都空着时只查看。名字按域名来检查。入口地址只接受 `http://` 或 `https://`。记下之后，状态目录里的 `link.json` 权限是 `0600`。页面负责记下。向外连是 `bucky desk entrance start`。

`desk entrance status` 的三句话：

| 情况 | 摘要 |
| --- | --- |
| 还没有名字 | 这台桌面还没有名字，也还没有云入口。 |
| 有名字，入口在自己身上 | 这台桌面叫 <名字>。公网入口在它自己身上。 |
| 有名字，也记下了云入口 | 这台桌面叫 <名字>。它向外连 <地址>。 |

只记下名字、没有 `--at` 时，公网入口算在这台桌面自己身上。这一版还不在这台桌面上对外听。`entrance use` 在名字和地址都记下时，摘要末尾再加上「还要从这台桌面向外连。」

桌面第一次登记时，入口发给一把令牌。令牌写进这台桌面的 `link.json`，入口上的 `desktops.json` 只留 SHA-256。同一个名字再登记、又不带这把令牌，摘要是「这台桌面已经接到入口。」令牌不出现在命令输出里。

别人用浏览器打开云主机，Host 等于某台已登记桌面的名字时，入口把这一次访问交给那台正连着的桌面，桌面再转到本机的 `127.0.0.1:1016`。`desk open` 仍只听本机，本机打开不查登录。从入口转进来的访问里，页面本身以及 `desk identity status`、`desk identity login` 可以直接到本机；其他 `POST` 要带这台桌面自己的 `Authorization: Bearer <token>`。没有这次登录时，桌面答 401，摘要是「请重新进入。」

| 情况 | 状态 | 正文 |
| --- | --- | --- |
| Host 对不上任何桌面，打开的是 `/` | 200 | 这是云入口。从桌面的名字打开。 |
| Host 对不上 | 421 | 这个地址不是接到入口的桌面。 |
| 这台桌面还没连上 | 503 | 这台桌面还没有连上。 |
| 排队已满 | 503 | 这台桌面忙。 |
| 桌面没有在时限里答 | 504 | 这台桌面没有应答。 |
| 本机页面没开 | 502 | 这台桌面没有打开。 |

`cloud status` 在没有桌面时说「还没有桌面接到这个入口。」有桌面时说「<n> 台桌面接到了这个入口。<m> 台正连着。」另一进程看到的是磁盘上的最近一次出现。这一版入口是 HTTP。队列记在 `cloud serve` 这个进程里。域名服务里的记录不改。ZoneGateway 不启动，也不能加入一个已经存在的 Zone。

## 这一版不做

不下载内核包，不写 `node_identity.json`，不启动 `node-daemon`。`kernel status` 只探测 3180 上是否已有进程在听。见 [非 UI 内核](非ui内核.md)。

本地查看：

```
cargo run -p buckydesk -- desk open
```
