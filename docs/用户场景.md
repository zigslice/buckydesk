# 用户场景

`http://127.0.0.1:1016` 是这个人的 BuckyOS 工作区。打开之后，他要能做自己的事：放文件、看今天要处理的、让 Agent 接着做、在需要时管这台电脑。

命令树是程序启动和保活这台机器的方式，见 [命令体系](命令体系.md)。它不出现在这个页面上。

名字、密码、文件、消息、认识的人、Agent、工作、模型和「这台电脑」里记下的事项都由本机服务保存。刷新之后，就绪的工作区会再要一次密码，文件还在。重置会清掉身份和这些内容。钥匙文件夹只记下路径。摘要会发给填写的模型服务地址。今天和「这台电脑」会说明内核是否已经在这台电脑上运行；这一版不拉起内核。

上游有好几套界面。下面先写每套界面想让人完成的事，再写成 BuckyDesk 上的一条连续故事。界面皮肤、端口和进程名不进故事。

## 上游界面各自想让人做什么

依据是 2026-10-20 的公开代码：`src/kernel/node_active`、`src/frame/desktop` 的应用登记和中文文案、`BuckyOSApp` 的现行需求。文案和实现冲突时，以人在那一屏要做的决定为准。

| 上游那一屏 | 人在那里做的决定 | BuckyDesk 里它变成 |
| --- | --- | --- |
| 激活向导第 1 步，创建或登录 SN(BNS) 账户，Beta 要邀请码 | 我在公网上叫什么名字 | 以后的「让别人找到这台电脑」。第一次打开不问 |
| 向导第 2 步，流量走 SN 转发，或自己有域名和 DNS | 别人怎么连到这台机器 | 同上，等人提出「我要在别处打开」再问 |
| 向导里的管理密码，至少 8 位 | 以后只有我能进这台个人系统 | 第一次打开就问。这是唯一当时就要的秘密 |
| 向导第 4 步，AI Provider，可以跳过 | 我的 Agent 用哪家模型 | 「给 Agent 接上模型」。跳过之后工作区仍能进 |
| 向导第 5 步，可选的 Telegram 用户 ID | 我在 Telegram 上说话时，系统认得是我 | Agent 的个人资料。和 Bot 的配置分开，和第一次打开分开 |
| 向导最后确认，然后「Personal Intelligence 已激活」 | 这台机器从此是我的 | 欢迎页做完，进入工作区。私钥备份交给人选定的位置，不在页面上铺开私钥 |
| BuckyOSApp：助记词、SN 用户名、签名、扫局域网或手填地址去打开别人的 3182 | 我是谁；我去把另一台正在等待的设备认领过来 | 「我去设置另一台电脑」是后一幕。默认故事是这一台电脑自己成为工作区 |
| Web Desktop 壳。文案写明它是布局、启动和同页窗口的薄层 | 我的事情都从这一张桌子开始，打开一个东西时桌子还在 | 桌面。网关、磁盘这些程序以窗口打开，关掉回到今天 |
| 文件。个人服务器上的文件夹、搜索、主题和每个文件的 AI 摘要 | 这是我的文件 | 「磁盘」 |
| 预览 | 我先看一眼，不必决定用哪个程序 | 文件里点开就是看 |
| HomeStation。待读 Feed、筛选、发布、关注 | 我今天要读的，以及我发出去的 | 「今天」承担待读；发布和关注留在后一幕 |
| MessageHub | 有人找我，或者系统有一件事在等我答复 | 「消息」。任务中心里「到 MessageHub 处理」的通知，在故事里就是一条消息 |
| 我的网络 | 我认识的人、群和关系 | 「我认识的人」 |
| 用户与 Agent | 谁可以用这台电脑，Agent 是谁，权限和是否在运行 | 「这台电脑上的人」和「Agent」。两件事不混成一个通讯录 |
| Agent 设置 | 我做出一个能替我做事的 Agent | 「做一个 Agent」 |
| AI 工作区。富文本、表格、资产、批注、可撤销的版本 | 我和 Agent 一起改一份会留下来的东西 | 「工作」 |
| CodeAssistant | 就这一段代码或这一次对话 | 「工作」里的一种，不是首页 |
| AI 中心。Provider、模型、用量、路由 | 模型从哪来、花了多少 | 「模型」 |
| 任务中心、Workflow | 什么在跑，什么跑完了，定时的有没有出错 | 「今天」里看得到进展；定义和历史在「工作」里 |
| 应用服务。安装、运行、失败原因。个人服务器只交回 `.pikg` | 我给这台系统加一个能力 | 「应用」 |
| 设置。主题、语言、Dead Zone、运行容器 | 这台工作区按我的习惯来 | 「这台电脑」里人能懂的那几项 |
| 诊断、Studio、Demos、系统测试、应用市场的占位图标 | 开发者走查壳和窗口 | 不进用户故事 |

文件服务、消息、HomeStation、OpenDAN、AI 计算、仓库和共享文件夹，在上游是各自的进程。人感受到的是上一表的那些决定。BuckyDesk 重做的是这些决定，底层仍只调用无界面内核，见 [非 UI 内核](非ui内核.md)。

## 这个人是谁

一台 Windows 或 macOS 电脑，一个人。他是这台 Zone 的第一个管理员。他没有 SN 账号，也不准备先理解 OOD、网关拓扑或端口。他知道自己的名字、一个密码，以及文件应该还在。

## 故事

### 1. 这台电脑变成我的

安装结束，浏览器打开 `http://127.0.0.1:1016`。页面只有一句人话：这台电脑会成为你的工作区。接着三件东西：

- 你的名字
- 管理密码，以及再输入一次。短于 8 位时告诉他长度不够
- 一个文件夹，用来保存只有你能打开这台工作区的那把钥匙

他确认之后，页面变成「正在准备你的工作区」。准备好了就进「今天」。

这一幕接的是向导里「设管理密码、然后激活成功」。公网名字、邀请码、流量怎么转发、模型和 Telegram 都留到他真的需要。钥匙写到他选定的文件夹，不在成功页上展开私钥。

底下，程序按 `provision` 的文件顺序写下这台单机的身份，再把内核拉起来。他看不到这些文件名。

做了一半再打开：页面说明上次没有完成，并停在原处。不能靠再点一次生成第二套身份。目录处于上游说的 `partial` 时，用这句话，而不是再走一遍欢迎。

这台电脑上已经有另一套 BuckyOS 占着同一批端口：页面说明已经有一套在运行，安装停住。不悄悄换端口。

### 2. 我进来

第二天他再次打开同一个地址。

工作区已经就绪：要密码。密码通过后进「今天」。

内核还在起来：停在「正在准备你的工作区」。这一屏不列出进程。

起不来：一句哪里失败了，以及日志在哪个文件夹。他可以再试一次。再试仍然是同一套身份。

### 3. 今天

「今天」是桌子。上面是此刻要他看的东西，按时间排：

- Agent 夜里留下的结果
- 还没答复的消息
- 没跑完或跑失败的工作

空的时候，桌面说下一步可以把文件放进来，或者先做一个 Agent。空桌子上不出现命令名。

左边是这台电脑上的程序：网关、磁盘、消息、关系、工作、Agent、模型和这台电脑。打开一个程序，它在桌面上成一个窗口；关掉之后回到今天。底下留着已经打开的程序。网关列出 BuckyOS 内核服务，并标明哪些端口已经在听。磁盘是他的文件。

### 4. 我的文件

他在「文件」里看到自己的文件夹。他可以新建、改名、移动、删除、搜索，点开一个文件先看一眼。搜索按他记得的词，也包括以后文件上的摘要。

他从自己的电脑拖一个 PDF 进来。文件出现在这个文件夹里。他可以对着它说「做成一份摘要，放到工作里」。摘要完成后，「今天」里有一条可以打开的结果。

这一幕接文件浏览和预览。人说的是「我的文件」。共享给家里另一台电脑、按主题浏览，是这一幕的后半：他在文件夹上选择「让另一台电脑打开」，再选那台电脑。页面不出现 NFS、SMB 或 DFS。

### 5. 有人找我

「消息」里是等他答复的对话，以及系统交给他的一件事。任务中心那种「去消息里处理」的通知，直接出现在这里，旁边有原来的工作。

他答复，或者标成以后再看。「今天」里对应的那一条消失。

「我认识的人」是好友、联系人和群。把一个人静音，只影响今天的阅读，不取消认识，也不改他能不能用这台电脑。这是 HomeStation 里静音的意图。

发布、关注和待读 Feed 是同一段关系的阅读面。第一版桌子上可以还没有 Feed。故事里它长在「今天」的下半：上面是要处理的，下面是要读的。

### 6. 我让它接着做

他在「Agent」里做一个助手，给它名字，并勾上它能看的文件夹和能不能发消息。做完之后，Agent 出现在「这台电脑上的人」旁边，状态是在工作还是停着。

「这台电脑上的人」是能登录这台工作区的人。第一个人就是他。以后可以再加。这和「我认识的人」是两份名单。上游把 Users & Agents 和 My Network 分开，就是这个原因。

他在「工作」里打开一份东西。那可以是一份文稿、一张表，或一次对着代码的对话。他和 Agent 都能改。每一次留下的修改能撤销。这是 AI 工作区的意图，不是一条没有归处的聊天。

他合上电脑之后，工作可以继续。再次打开「今天」，看得到它做到哪、有没有失败。定时要跑的事情，失败时出现在今天，平时不必打开一张时刻表。

Telegram 上认人是这一幕的后手：他在 Agent 的资料里填上自己的 Telegram 数字 ID。Bot 本身在创建 Agent 时另设。向导把这两件事情分开，故事里也分开。

### 7. 我给它一个模型

Agent 还没有模型时，他让 Agent 做事，页面告诉他要先接上一个模型，并给出入口。他可以现在接，也可以先回到今天。

「模型」里他选择一家服务，填入自己的密钥，看到今天和这个月大概用了多少。密钥只在这里出现。这是 AI 中心的意图，也是向导里允许跳过的那一步。

### 8. 我让别人找到这台电脑

他在「这台电脑」里选择「在别处打开」。这时才问向导的前两步在问的事：用一个现成的名字，还是用自己已经拥有的域名。需要邀请码或账号时，在这一步说明。做完之前，工作区一直只在这台电脑的浏览器里。

「我去设置另一台电脑」也在这里。他输入那台机器的地址，或在同一网络里找到一台正在等待的机器，然后在 BuckyDesk 里完成那台机器的设置。BuckyOSApp 用独立窗口去开 3182。BuckyDesk 把这件事留在 1016，不把「去配置别人」当成第一次打开的主线。

### 9. 我离开，或者上次没做完

「这台电脑」里他看得到：工作区是否就绪、名字、密码、钥匙备份在哪个文件夹、语言。

退出和重置是两个动作。退出后文件还在，下次打开要密码。重置会清掉工作区里的文件和身份，页面在他确认之前写明会丢掉什么。

覆盖安装之后，他上次放进「文件」的东西还在。卸载之后进程停了，页面曾经承诺保留的文件夹还在。

升级跨了一个不保证兼容的版本时，先让他把钥匙和文件备份再继续。

## 工作区长什么样

首页是桌面，今天放在桌面右侧。程序从左边打开：

| 地方 | 人来这里做什么 |
| --- | --- |
| 今天 | 看要处理的结果、消息和没做完的工作 |
| 网关 | 看 BuckyOS 的服务在不在这台电脑上听着 |
| 磁盘 | 放、找、看自己的文件 |
| 消息 | 答复人和系统 |
| 我认识的人 | 好友、联系人、群 |
| 工作 | 和 Agent 一起留下一份可撤销的东西 |
| Agent | 做出助手，并决定它能碰什么 |
| 模型 | 接上模型，看用量 |
| 应用 | 给这台系统加一个能力 |
| 这台电脑 | 密码、钥匙、是否就绪、在别处打开、退出和重置 |

「这台电脑上的人」放在「这台电脑」里，因为它决定谁能进这台工作区。

## 命令壳放在哪

`bucky` 和 `POST /api/exec` 仍是同一棵树，分成 `desk` 和 `cloud`。工作区在人做完一个决定之后调用 `desk`：设好密码就写入身份，放进文件、做出 Agent、接上模型、留下工作，都写在这台电脑上。退出只离开这一次，并收回公网入口的登录。他在「这台电脑」里写下自己的域名时，调用的是 `cloud domain`。页面会告诉他把这个名字和 `ood1` 指到哪一个地址。云主机上运行 `bucky cloud serve` 之后，80 提供页面，443 用这台机器签发的证书提供同一页面。别人打开时浏览器会提醒，直到换上自己带来的证书。先登录再进入。ZoneGateway 留到内核包接上之后。

他不在页面上挑选 `kernel status` 或 `identity activate`。准备中、就绪、失败、上次没做完，是这棵树的结果翻译成的四句话。

## 先做成哪几幕

按故事的顺序做页面，每一幕等人能做的那件事真的发生，不先排一排空菜单。

第 1 幕到第 8 幕，以及第 9 幕里的就绪、钥匙位置、退出和重置，已经由本机服务保存。拉起内核留到内核包接上之后。

1. 第 1 幕。名字、密码、钥匙备份，以及上次没做完、已经有一套在运行。
2. 第 2 幕。准备中、进不去、密码。
3. 第 3 幕。今天是桌面。程序以窗口打开。没有文件和 Agent 时，告诉他下一步，而不是列出命令。
4. 第 9 幕里他天天会碰到的那几项：是否就绪、钥匙在哪、退出和重置是两个动作。

第 4 幕到第 8 幕的文件、消息、认识的人、工作、Agent、模型和对外的名字，已经记在这台电脑上。记下域名并在云主机上执行 `bucky cloud serve` 之后，别人按页面上的地址把域名指过来，就可以打开同一页面，先登录再进入。443 先用这台机器签发的证书。ZoneGateway 还没有做。另一台电脑先记下地址。网关可以打开：它只报告服务有没有在听，不假装内核已经拉起。
